## 序言：环境那些事

> 这篇记的是开始写 C 之前踩的坑。跟语法没关系，但每一个都够卡一整天。
> 顺序是连着的：装软件 → 建仓库 → 写代码 → 加中文注释 → 确认它真的生效。跳一步，后面那一节的怪现象就来了。

### 序.1 装 VS 的时候该勾什么

（本机是 Visual Studio 2026 Community，版本号 18.10.2，帮助 → 关于 里能查到。下面写的 v145 是 2026 的工具集编号，用 VS 2022 的话对应 v143，其余都一样。）

下载下来的 `VisualStudioSetup.exe` 才几 MB，双击之后弹出一个很小的窗口，选项一堆，完全不知道该勾什么、也不知道要装多大。我当时最纠结的是右边那栏「安装详细信息」——SDK、生成工具列了一长串，看着像是要自己挨个勾一遍。

其实不用。

那个 exe 只是个引导器，不是 VS 本体。真正的安装内容在它联网之后列出来的「工作负载」里。C 语言只需要勾一个：「使用 C++ 的桌面开发」。

之所以叫 C++ 不叫 C，是因为 MSVC 一个编译器同时管 C 和 C++，微软把它们打包进同一个工作负载了，列表里压根没有单独的「C 语言」这一项。

**那右边那一串呢**

勾完工作负载，右边会**自动列出并预先勾好**一批组件。那栏不是待办清单，是已经替你选完的东西。微软把它分成三档：

| 档位 | 里面有什么 | 要不要动 |
| --- | --- | --- |
| Required | MSBuild、C++ 核心功能、C++ 核心桌面功能、Windows Universal C Runtime | 取消不了 |
| Recommended | **MSVC v145 生成工具**、**Windows 11 SDK**、C++ CMake 工具、AddressSanitizer、vcpkg | 能取消，**但别取消** |
| Optional | C++ ATL / MFC、C++/CLI 支持、MSVC v140 / v142 旧工具集 | 初学用不上，可以不勾 |

所以准确的说法是：不用手动勾，但不能取消勾。

SDK 尤其别动。它提供 Windows API 的头文件和库，VS 建项目那一刻就要用到，取消掉直接编译失败。

「单个组件」那个标签页第一次装的时候也别打开，那是后来补东西用的（比如发现缺某个 SDK 版本、要装旧工具集）。进去容易把默认项勾乱。

**几件小事**

- 安装位置可以改到 D 盘。默认在 C 盘，连同 SDK 十几个 G。
- 语言包：装中文的话报错信息也是中文，拿去搜索很难找到答案。建议用英文界面，或者至少养成看错误代码的习惯（`C4996`、`C4819` 这种）。
- 装完重启一次再开 VS。

怎么确认装好了：编译时看输出窗口的命令行，出现 `/Fd"...\vc145.pdb"` 就说明用的是 v145 工具集（VS 2022 那边显示 `vc143`）。

### 序.2 仓库和 VS 项目不是一回事

VS 说的「项目」和我想要的「仓库」不是一个东西。仓库是文件夹，VS 项目是 `.vcxproj` 文件。一开始不知道先建哪个、怎么让它们对上。

三个概念分开看：

| 名称 | 是什么 | 谁建的 |
| --- | --- | --- |
| 仓库 repository | 带 `.git` 的文件夹 | `git init` |
| 解决方案 solution | `.sln`，用来组织多个项目 | VS |
| 项目 project | `.vcxproj`，源文件 + 编译设置 | VS |

我现在的目录是这样：

```
F:\Github_C_learning\
├─ .git\
├─ ch_01_Helloworld\
├─ ch_02_increment_and_compound\
├─ ch_03_loop_sum_for\
├─ ch_03_if_else_nested\
├─ ch_03_guess_number\
└─ Directory.Build.props
```

先在磁盘上建文件夹、在这里 `git init`，再往里建项目。

**建项目时的三个选择**

- 模板选**「空项目」**。选「控制台应用」会自带一堆用不上的代码和头文件。
- **「将解决方案和项目放在同一目录」别勾**。勾了会多套一层目录，路径很乱。
- 源文件手动建 `.c`，**别建 `.cpp`**。VS 按后缀挑编译器：`.c` 走 C 规则，`.cpp` 走 C++ 规则，两者语法并不一样——后来碰到的"万能头"那些事，全是 C++ 那边的问题。

**一个项目只能有一个 `main`**

两个 `.c` 各写一个 `main`，链接时报「找到一个或多个多重定义的符号」。想在同一个仓库里放很多小程序，就一个小程序一个子文件夹、一个项目。

**最容易被骗的一点**

「解决方案资源管理器」里显示的树是 VS 的**虚拟**目录，不等于磁盘上真实的结构。要看真实文件，点工具栏的**「显示所有文件」**图标。

### 序.3 一用 scanf 就被警告拦下

第一次用 `scanf`，编译直接给：

```
error C4996: 'scanf': This function or variable may be unsafe.
             Consider using scanf_s instead.
```

微软认为 `scanf` 不检查缓冲区长度、可能溢出，于是建议你换它自己的 `scanf_s`。但 `scanf_s` 不是标准 C，换到 gcc / Clang 就编译不过，学标准 C 不能靠它。

解决办法是在 `.c` 文件**第一行**写：

```c
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>
```

必须写在 `#include` **之前**。`#define` 是预处理指令，按从上到下的顺序生效；写在 `#include` 后面时头文件已经处理完了，这个开关没赶上，等于白写。

不想每个文件都写，也可以在 项目属性 → **C/C++ → 预处理器 → 预处理器定义** 里加 `_CRT_SECURE_NO_WARNINGS`，一次配好整个项目。我两个都留着：项目属性配好，文件首行也写——换电脑、换环境时不至于失效。

这就是这份笔记里每个 `.c` 文件首行都有那句 `#define` 的原因。

### 序.4 加了中文注释之后编译不过

代码一行没改，只是写了中文注释，就冒出这两个：

```
warning C4819: 该文件包含不能在当前代码页(950)中表示的字符。
error   C1075: 找到"{"的平衡之前遇到文件结束
```

（有时候报的是 C2143、C2059，看着更莫名其妙。）

根因是文件存成了**无 BOM 的 UTF-8**，而 VS 按系统 ANSI 代码页去读它。中文 Windows 的 ANSI 代码页是 **950（Big5，繁体）** 或 936（GBK，简体）。用 Big5 的规则去读 UTF-8 的字节流，字节配对就全乱了。

繁体环境尤其容易中招。Big5 是双字节编码，**尾字节范围 `0x40–0x7E`**，这个区间几乎覆盖了所有 ASCII 可见字符——英文字母、`{`、`}`、`[`、`]`、`|`、`~`、`@`、`#`、`$` 全在里面。

于是会发生这种事：

```c
printf("結果");    // 漢字註釋
{
```

汉字"註"的第二个字节如果落在 `0x7B`（正好是 `{` 的 ASCII 码），VS 就把它当成**一个左大括号**；反过来，注释后面那个真的 `{` 也可能被当成某个汉字的尾字节**吞掉**。大括号数目从此对不上，于是报 `C1075`——看起来像是括号写漏了，实际一个括号都没错。

**解决办法：给编译器加 `/utf-8`**

明确告诉它源文件和执行字符集都按 UTF-8 读。有三个位置可以加，越往下越稳：

| 位置 | 怎么做 | 生效范围 |
| --- | --- | --- |
| 单项目 | 项目属性 → **C/C++ → 命令行 → 其他选项**，填 `/utf-8` | 当前项目 |
| 用户级 | 写进 `%LOCALAPPDATA%\Microsoft\MSBuild\v4.0\Microsoft.Cpp.x64.user.props`（Win32 版同理） | 这台电脑上 VS 的所有项目 |
| 仓库级（推荐） | 仓库根目录放一个 `Directory.Build.props` | 这个仓库下所有项目 |

`Directory.Build.props` 的内容：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Project>
  <ItemDefinitionGroup>
    <ClCompile>
      <AdditionalOptions>/utf-8 %(AdditionalOptions)</AdditionalOptions>
    </ClCompile>
  </ItemDefinitionGroup>
</Project>
```

怎么确认生效：项目属性 → **C/C++ → 命令行 → 其他选项**，看到 `/utf-8` 就成功了（字是**斜体**，斜体表示继承自上层的属性表，不是这个项目单独设的）。

### 序.5 属性表装上了，命令行里却没有 /utf-8

一键安装脚本打印 `DONE!`，诊断脚本也说 props 文件在、内容里确实有 `utf-8`。但打开项目属性，「其他选项」是空的，中文注释照样报错。

原因是**项目是在装属性表之前建的**，VS 启动时已经把它的设置读进缓存了。属性表只对**重启后重新加载的项目**生效，光点「重新生成」没用。

正确的顺序：

```
装属性表 → 完全关掉 VS → 重新打开 VS → 打开项目 → 重新生成
```

**后来为什么改用 `Directory.Build.props`**

| 对比项 | 用户属性表 | `Directory.Build.props` |
| --- | --- | --- |
| 依赖 `%LOCALAPPDATA%` 路径 | 是 | 否 |
| 依赖 VS 版本（v4.0 / v17 …） | 是 | 否 |
| 缓存问题 | **有** | 没有，每次生成都读 |
| 换电脑 / 重新 clone 后还生效 | 否 | **是**，文件在仓库里 |

最后是两层都在：用户属性表管整台电脑，`Directory.Build.props` 管这个学习仓库，任一层生效就够。

### 序.6 几个一开始搞不懂的 VS 概念

- **生成 / 重新生成 / 清理**：生成只编译改动过的；重新生成是全部重来。改了编译选项之后要用**重新生成**。
- **Debug / Release**：平时用 Debug（有调试信息、不做优化，变量没初始化会被填成 `0xCCCCCCCC`）。Release 会优化，有些 bug 只在 Release 下出现。
- **x64 / x86**：目标平台，要和装的 Windows SDK 对得上。初学选 x64 就行。
- **F5 窗口一闪而过**：F5 是「启动调试」，程序结束窗口就关。要看结果按 **Ctrl+F5**（开始执行，不调试），或者在 `return 0;` 前加 `getchar();`。
- **错误列表只显示一行**：完整的报错、警告原文在下面的**「输出」**窗口里，错误列表只是摘要。
- **报错行号不准**：括号漏写、中文编码这类错，编译器往往到**文件末尾**才发现问题，行号会指向最后一行，要往回找。
- **排除出项目 vs 删除**：排除只是不参与编译，文件还在磁盘上；删除是真删。
- **一个项目只能有一个 `main`**：见[序.2](#序2-仓库和-vs-项目不是一回事)。

### 第 1 章 Hello World：C 程序的结构

**源文件：`Helloworld.c`（`ch_01_Helloworld`）**

```c
// 关闭 VS 对 scanf 等函数的安全警告
#define _CRT_SECURE_NO_WARNINGS
//頭文件
#include <stdio.h>

//主函數，一個程序只能有一個主函數

int main(void)//注意拼寫與引用函數是否存在

//int表示整數類型，main表示主函數，void表示無參數

{

	//打印，輸出到屏幕，\n表示換行

	printf("Day 1 of Learning C: Starting with Hello World\n");//注意添加分號

	//約定0返回表示程序正常結束

	return 0;

}
```

输出：

```
Day 1 of Learning C: Starting with Hello World
```

#### 1.1 语法点

| 代码 | 含义 |
| --- | --- |
| `#define _CRT_SECURE_NO_WARNINGS` | 关闭 VS 对 `scanf` / `fgets` 的安全警告。**必须在所有 `#include` 之前** |
| `#include <stdio.h>` | 引入输入输出工具，`printf` 靠它才能用 |
| `int main(void)` | 主函数，**一个程序只能有一个**，程序从它开始执行 |
| `int` / `main` / `void` | 整数类型 / 主函数的固定名字 / 无参数 |
| `printf("...");` | 打印到屏幕 |
| `\n` | 换行 |
| `return 0;` | 约定返回 0 表示程序正常结束 |
| `//` 与 `/* */` | 单行注释 / 多行注释（第 4 章用到） |

#### 1.2 易错点

- `main` 拼成 `mian`、`Main` 会编译报错。
- 每条语句结尾必须有 `;`；函数体的 `{ }` 后面**不**加 `;`。
- 一个项目里两个 `.c` 各写一个 `main`，链接时报"找到一个或多个多重定义的符号"。

### 第 2 章 圆的面积与周长：变量与 printf 占位符

**源文件：`Circle_calc.c`（`ch_01_Circle_calc`）**

```c
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>

int main(void)//int一個整數，main為主函數，void表示無參數
{
	int r;//int一個整數，r為半徑
	float c, s;//float一個浮點數，c為圓周長，s為圓面積

	r = 5;//半徑為5
	c = 2 * 3.14159 * r;//圓周長公式為2πr
	s = 3.14159 * r * r;//圓面積公式為πr^2

	printf("r=%d,c=%.2f,s=%.2f\n", r, c, s);//%d整數佔位符，%.2f浮點數保留兩位小數
	return 0;
}
```

输出：

```
r=5,c=31.42,s=78.54
```

#### 2.1 先声明，后使用

```c
int r;      // 声明：告诉电脑"我要一个装整数的盒子，叫 r"
r = 5;      // 赋值：把 5 装进去

float c, s; // 一条语句声明多个同类型变量，逗号隔开

int r = 5;  // 声明 + 赋值合并成一步 = 初始化
```

#### 2.2 数据类型

| 类型 | 名称 | 能装什么 |
| --- | --- | --- |
| `int` | 整型 | 整数（5、12、-3） |
| `float` | 单精度浮点型 | 带小数点的数（约 6~7 位有效数字） |
| `double` | 双精度浮点型 | 带小数点的数（约 15~16 位有效数字），见第 3 章 |

#### 2.3 printf 占位符

```c
printf("r=%d,c=%.2f,s=%.2f\n", r, c, s);
```

**占位符的数量和顺序，必须与后面的变量一一对应。**

| 占位符 | 类型 | 说明 |
| --- | --- | --- |
| `%d` | `int` | 整数 |
| `%f` | `float` / `double` | 浮点数，默认 6 位小数 |
| `%.2f` | `float` / `double` | 浮点数，保留 2 位小数 |
| `%%` | — | 输出一个真正的 `%` 字符 |
| `\n` | — | 换行 |

#### 2.4 易错点

- 占位符必须与类型配对：`int` 用 `%d`、`float` 用 `%f`，混用会打印出乱数。
- `%.2f` 里的 `.2` 是"保留 2 位小数"，不是"除以 2"。
- C 没有平方符号，πr² 要写成 `3.14159 * r * r`。

### 第 3 章 double 与 scanf：更高精度与键盘输入

**源文件：`Circle_calc_double.c`（`ch_01_Circle_calc_double`）**

与第 2 章同一道题，只改了三处：`float` → `double`、半径固定 → 键盘读入、输出 `%.2f` → `%.2lf`。

```c
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>

int main(void)
{
    // 变化 1：float 换成 double（双精度，能存更多位小数）
    double r;          // 半径
    double c, s;       // 周长 c、面积 s

    // 变化 2：读入 double，scanf 必须用 %lf（l 是字母 L 的小写）
    printf("Please enter the radius: ");
    scanf("%lf", &r);  // &r 取地址，和第 4 章的 sscanf 同理

    c = 2 * 3.14159 * r;      // 周长 = 2πr
    s = 3.14159 * r * r;      // 面积 = πr²

    // 变化 3：printf 里 double 写 %.2lf（写 %.2f 也可以）
    printf("r=%.2lf, c=%.2lf, s=%.2lf\n", r, c, s);

    return 0;
}
```

输入 `5` 后的输出：

```
Please enter the radius: r=5.00, c=31.42, s=78.54
```

#### 3.1 scanf 与 printf 的占位符不一样

| 场景 | `float` | `double` |
| --- | --- | --- |
| `printf`（输出） | `%f` / `%.2f` | `%f` / `%.2f`（写 `%lf` 也行） |
| `scanf`（输入） | `%f` | **必须 `%lf`** |

> 口诀：**输入时两种类型要分开（`%f` / `%lf`），输出时不用分。**

```c
scanf("%lf", &r);   // "格式" + "地址"，两样都不能少
```

#### 3.2 易错点

- `scanf` 后面的变量必须加 `&`：写成 `scanf("%lf", r)` 是错的。
- `scanf` 的格式串里**不要加 `\n`**，否则程序会多等一次回车，看起来像卡住了。
- 本程序不检查输入合法性（输字母会出错），容错写法见第 4 章。

### 第 4 章 比较两个数：容错输入与自定义函数

**源文件：`compare_two_numbers.c`（`ch_01_compare_two_numbers`）**

```c
/*
 * 程序名：compare_two_numbers.c
 * 功能：从键盘读取两个整数（用英文逗号隔开），
 *       若格式错误或未使用英文逗号，则提示并重新输入，
 *       最后输出两个数中的较大值。
 */

#define _CRT_SECURE_NO_WARNINGS        // 关闭 VS 对 scanf 等函数的安全警告
#include <stdio.h>                    // 提供 printf / fgets / sscanf
#include <string.h>                   // 提供 strchr，用于查找字符

 /* 自定义函数：返回两个整数中的较大值 */
int Max(int a, int b)
{
    if (a > b)                        // 若 a 大于 b
        return a;                     // 返回 a
    else                              // 否则
        return b;                     // 返回 b
}

int main()
{
    int x, y;                         // 存放用户输入的两个整数
    char line[100];                   // 字符数组，存放用户整行输入
    int ok = 0;                       // 标记：是否已成功读到两个整数（0=否，1=是）

    printf("Please enter two integers separated by an English comma\n");

    /* 只要还没成功读到两个数，就一直循环 */
    while (!ok)
    {
        printf("> ");                 // 输入提示符，提示用户在此输入

        /* fgets：从键盘(stdin)读取一整行，存入 line
         * sizeof(line) 限制最多读取的字符数，防止缓冲区溢出 */
        fgets(line, sizeof(line), stdin);

        /* strchr：在 line 中查找英文逗号 ','
         * 若返回 NULL，说明没找到英文逗号 */
        if (strchr(line, ',') == NULL)
        {
            printf("Error: no English comma ',' found. Please try again!\n");
            continue;                 // 跳过本次剩余代码，回到循环开头重新输入
        }

        /* sscanf：从字符串 line 中按 "%d,%d" 格式解析两个整数
         * 返回值等于成功读到的数据个数，期望为 2 */
        if (sscanf(line, "%d,%d", &x, &y) == 2)
        {
            ok = 1;                   // 成功读到两个，设标记为 1，跳出循环
        }
        else
        {
            printf("Error: invalid format. Enter two numbers separated by an English comma (e.g. 12,13)!\n");
        }
    }

    printf("The larger value is: %d\n", Max(x, y));   // 调用 Max 并输出结果
    return 0;                         // 程序正常结束
}
```

#### 4.1 程序结构

1. 开头：`#define` 和 `#include`（告诉电脑要什么工具）
2. `Max` 函数：自己写的比大小工具，放在 `main` 前面
3. `main` 函数：程序主体，调用上面的工具

#### 4.2 用到的工具

| 代码 | 来源 | 作用 |
| --- | --- | --- |
| `fgets(line, sizeof(line), stdin)` | `stdio.h` | 从键盘读**一整行**，存到 `line`，最多读 `sizeof(line)` 个字符 |
| `strchr(line, ',')` | `string.h` | 在字符串里找字符，返回位置；没找到返回 `NULL` |
| `sscanf(line, "%d,%d", &x, &y)` | `stdio.h` | 从字符串按格式读数据，**返回值 = 成功读到的个数** |
| `&x` | — | 取地址：函数要往盒子里装东西，就得知道盒子在哪 |

**用到了什么工具，就包含对应的头文件。**

> 为什么整行读：用 `scanf` 时用户输错会卡死；先整行读进来再慢慢检查就不会。

#### 4.3 自定义函数 Max

```c
int Max(int a, int b)    // int = 返回整数，Max = 函数名，(int a, int b) = 两个形参
{
    if (a > b) return a;
    else       return b;
}
```

**`Max(x, y)` 整个表达式的值就是返回的那个数**，所以可以直接塞进 `printf`：

```c
printf("The larger value is: %d\n", Max(x, y));
//                                     ↑ 这里就是"较大的数"
```

#### 4.4 `ok` 标记 + `while (!ok)`

```c
int ok = 0;      // 0 = 还没成功
while (!ok)      // ! 取反：ok 为 0（假），!ok 为 1（真），循环继续
{
    ...
    if (sscanf(...) == 2) ok = 1;   // 读对了就翻转标记，循环结束
}
```

| 情况 | `strchr` 返回值 | `== NULL` 是真是假 |
| --- | --- | --- |
| 找到了逗号 | 一个真实位置 | 假 |
| 没找到逗号 | `NULL`（"没有"） | 真 |

#### 4.5 易错点

- `Max` 必须写在 `main` 前面，否则报"未定义标识符"。
- `ok` 初值必须是 0，读对了才改成 1，别写反。
- `strchr(...) == NULL` 是"**没**找到"。
- `sscanf` 读数据要加 `&`。
- `char line[100]` 用方括号 `[ ]`，不是 `char line == 100`；规定大小的是 `[100]`，`sizeof(line)` 只是"查一下有多大"。
- `continue` 是"跳过本次剩余代码、回到循环开头"；`return 0` 是整个函数结束。

### 第 5 章 运算符优先级与结合性

**源文件：`operator_precedence.c`（`ch_02_operator_precedence`）**

> 一句话：**优先级决定谁先算，结合性决定同级时从左还是从右。**

#### 5.1 优先级表（从高到低）

| 层级 | 运算符 | 结合性 |
| --- | --- | --- |
| 1（最高） | `()` | — |
| 2 | `++` `--` `!` `-`（负号）`sizeof` | 从右到左 |
| 3 | `*` `/` `%` | 从左到右 |
| 4 | `+` `-` | 从左到右 |
| 5 | `<` `<=` `>` `>=` | 从左到右 |
| 6 | `==` `!=` | 从左到右 |
| 7 | `&&` | 从左到右 |
| 8 | `\|\|` | 从左到右 |
| 9（最低） | `=` `+=` `-=` `*=` `/=` `%=` | 从右到左 |

**记不住就加括号，括号永远最高。**

#### 5.2 逐条验证

| 规则 | 代码 | 结果 |
| --- | --- | --- |
| 括号最高 | `2 + 3 * 4` / `(2 + 3) * 4` | 14 / 20 |
| 单目仅次于括号 | `int i = 5; i++ * 2` | 10，之后 `i` 变 6 |
| `!` 取反 | `!0` / `!1` | 1 / 0 |
| 乘除余高于加减 | `10 - 6 / 2` | 7 |
| 同级从左到右 | `10 % 3 * 2` | 2 |
| 比较高于 `==` | `3 + 2 == 5` | 1（真） |
| `&&` 高于 `\|\|` | `0 \|\| (1 && 0)` | 0 |
| 赋值最低 | `u = v = 5`（从右到左） | `u=5, v=5` |
| 结合性从左到右 | `10 - 3 - 2` / `2 * 3 / 2` | 5 / 3 |

> `5 > 3 == 1`、`0 || 1 && 0` 不加括号结果也对，但可读性差、编译器会告警，**实际写代码要加括号**。

#### 5.3 实际输出

```
=== 1. parentheses ===
2 + 3 * 4 = 14
(2 + 3) * 4 = 20

=== 2. unary operators ===
i++ * 2 = 10, i = 6
!0 = 1, !1 = 0

=== 3. * / % before + - ===
10 - 6 / 2 = 7
10 % 3 * 2 = 2

=== 4. comparison before == and != ===
3 + 2 == 5 -> 1
(5 > 3) == 1 -> 1

=== 5. && before || ===
0 || (1 && 0) = 0

=== 6. assignment is last ===
u = v = 5  -> u=5, v=5
w = 2 + 3  -> w=5

=== 7. associativity ===
10 - 3 - 2 = 5
2 * 3 / 2 = 3

=== traps ===
a == 5 -> 0 (0 means false)
```

#### 5.4 三个坑

```c
if (a = 5)        // 错：= 是赋值，把 5 装进 a 再判断真假
if (a == 5)       // 对：== 才是比较

if (a & b == 0)   // 错：等价于 a & (b == 0)，因为 == 优先级高于 &
if ((a & b) == 0) // 对

i++ + ++i         // 错：一个表达式里又用又改同一个变量，结果不确定
```

> 结合性只保证运算符的结合方向，**不保证**操作数里函数调用 / 自增的求值顺序。凡是有副作用的操作，不要依赖顺序。

### 第 6 章 自增自减与复合赋值

**源文件：`increment_and_compound.c`（`ch_02_increment_and_compound`）**

> 学习方法：先在纸上算一遍，再编译运行核对。

#### 6.1 复合赋值：运算符放左边，只写一个 `=`

| 简写 | 等价写法 |
| --- | --- |
| `sum += i;` | `sum = sum + i;` |
| `sum -= i;` | `sum = sum - i;` |
| `sum *= i;` | `sum = sum * i;` |
| `sum /= i;` | `sum = sum / i;` |
| `sum %= i;` | `sum = sum % i;` |

本程序的推演（`sum` 从 0 开始）：

| 语句 | 之后 `sum` 的值 |
| --- | --- |
| `int sum = 0;` | 0 |
| `sum += 3;` | 3 |
| `sum *= 2;` | 6 |
| `sum -= 1;` | 5 |
| `sum /= 2;` | **2**（整数除法砍掉小数，不是 2.5） |
| `sum %= 2;` | 0 |

#### 6.2 `++` `--`：单独成行时前后没区别

```c
int a = 5; a++;   // a = 6
int b = 5; ++b;   // b = 6，与 a++ 效果完全相同
int c = 5; c--;   // c = 4
```

> 只有单独成行时前后才没区别；一旦放进更大的表达式，前后完全不同。

#### 6.3 前 ++ 与 后 ++（重点）

| 写法 | 口诀 | 含义 |
| --- | --- | --- |
| `i++` | **先用后加** | 先拿 `i` 当前的值去用，用完再加 1 |
| `++i` | **先加后用** | 先让 `i` 加 1，再用新值 |

```c
int i = 5; int x = i++;   // x = 5, i = 6
int j = 5; int y = ++j;   // y = 6, j = 6
int m = 5; int p = m--;   // p = 5, m = 4
int n = 5; int q = --n;   // q = 4, n = 4
```

#### 6.4 实际输出

```
=== Part 1: compound assignment ===
sum = 0

=== Part 2: ++ and -- (standalone) ===
a = 6, b = 6, c = 4

=== Part 3: i++ vs ++i ===
x = 5, i = 6
y = 6, j = 6

=== Part 4: m-- vs --m ===
p = 5, m = 4
q = 4, n = 4
```

#### 6.5 易错点

- 别在一个表达式里又用又改同一个变量（`i++ + ++i`），结果不确定。
- `++` / `--` 只能用于**变量**，`5++`、`(a+b)++` 都是错的。
- 复合赋值只写一个等号：`sum += 3` 对，`sum =+ 3` 错（等于 `sum = +3`）。

### 第 7 章 for 循环：求和、求积与循环变量

**源文件：`loop_sum_for.c`（`ch_03_loop_sum_for`）**

```c
#define _CRT_SECURE_NO_WARNINGS
#include <stdio.h>

int main(void)
{
    int i, sum = 0;

    /* 求 1 + 2 + ... + 100 */
    for (i = 1; i <= 100; i++)
    {
        sum += i;          // 等价于 sum = sum + i
    }

    printf("sum = %d\n", sum);

    return 0;
}
```

输出：

```
sum = 5050
```

#### 7.1 for 的三段

```c
for (初始化; 条件; 步进)
    循环体;
```

| 段 | 例子 | 什么时候执行 | 执行几次 |
| --- | --- | --- | --- |
| 初始化 | `i = 1` | 进循环**之前** | **1 次** |
| 条件 | `i <= 100` | 每轮**开始**判断 | n + 1 次（最后一次判断为假，退出） |
| 步进 | `i++` | 每轮**结束** | n 次 |
| 循环体 | `sum += i;` | 条件成立时 | n 次 |

初始化只执行 1 次这件事很关键。累加器归零写在这里（`for (i = 1, sum = 0; ...)`）是**合法而且推荐**的——跟单独写一行 `sum = 0;` 完全等价，好处是归零跟着循环走，复制、调换顺序时不会漏。

| 写法 | 结果 | 说明 |
| --- | --- | --- |
| `for (i = 1, sum = 0; i <= 50; i += 2)` | 625 | 在初始化段，只执行 1 次 |
| `for (i = 1; sum = 0, i <= 50; i += 2)` | 0 | 落到条件段，每轮开始都清回 0 |
| `for (i = 1; i <= 50; i += 2, sum = 0)` | 0 | 落到步进段，每轮结束都清回 0 |

逗号**不是**分隔符。`for (A; B; C)` 只有 **2 个分号**，段内放多个赋值才用逗号。

#### 7.2 求和跟求积，初值不一样

| | 求和 | 求积 |
| --- | --- | --- |
| 累加器初值 | `sum = 0` | **`acc = 1`** |
| 运算 | `sum += i` | `acc *= i` |
| 起点 | 任意 | **必须 ≥ 1** |
| 例子 | 1+2+…+20 = **210** | 5! = **120** |

求积的初值为什么是 1 不是 0：0 在乘法里是**吸收元素**，`0 × 任何数 = 0`，结果永远是 0。加法里 0 才安全（`0 + 任何数 = 那个数`）。

求积的起点也必须 ≥ 1，从 0 开始的话 `acc = 1 × 0 = 0`，后面乘什么都是 0。

```c
/* 求 5! = 1×2×3×4×5 */
int i, acc;
for (i = 1, acc = 1; i <= 5; i++)
    acc *= i;
printf("5! = %d\n", acc);      // 120
```

#### 7.3 for 改成 while 要补什么

`for` 帮你做的三件事，写成 `while` 之后**都得自己补**：

| `for` 的位置 | 改 `while` 后放哪 |
| --- | --- |
| 第一段 初始化 `i = 1` | `while` **前面** |
| 第二段 条件 `i <= 20` | `while (...)` 的**括号里** |
| 第三段 步进 `i++` | 循环体**最后一句** |

```c
/* for 版 */
for (i = 1; i <= 20; i++)
    sum += i;

/* while 版：输出完全一样，都是 210 */
i = 1;                  // 第一段搬到 while 前面
while (i <= 20)         // 第二段留在括号里
{
    sum += i;
    i++;                // 第三段搬到循环体最后
}
```

少任何一条，循环都是坏的：不初始化 → `i` 是垃圾值，次数不确定；不写步进 → 死循环（控制台按 **Ctrl + C** 中断）。

#### 7.4 循环结束后，i 是多少

**循环结束时，`i` = 第一个让条件不成立的值。**

不是「最后一个进循环的值」——这两者永远差一步，因为步进在条件判断之前执行。

| 循环 | `i` 的完整序列 | 最后一个进循环 | 结束后 `i` |
| --- | --- | --- | --- |
| `i = 0; i < 3; i++` | 0 1 2 \| 3 | 2 | **3** |
| `i = 1; i <= 5; i++` | 1…5 \| 6 | 5 | **6** |
| `i = 10; i >= 1; i -= 2` | 10 8 6 4 2 \| 0 | 2 | **0** |
| `i = 2; i <= 10; i += 3` | 2 5 8 \| 11 | 8 | **11** |

步进为 1 时有个快捷记法：

- 没有等号（`<` `>`）→ 结束后 `i` 就是判断用的那个数
- 有等号（`<=` `>=`）→ 结束后 `i` 是那个数 ± 1（往上 +1，往下 −1）

**步进大于 1 时这个快捷法失效。** `for (i = 1; i <= 10; i += 4)` 的 `i` 是 `1 5 9 | 13`，边界是 10，但 `i` 从 9 直接跳到 **13**，既不是 10 也不是 11。这种情况**必须把序列写出来**。

通用做法：**先写出 `i` 的完整序列 → 筛掉不满足条件的 → 剩下的拿来算。** 序列错了，加法再熟也白搭。

这题的坑在于**不报错、不崩溃**，只是值大 1。等学到数组：

```c
int a[5] = {1,2,3,4,5};
for (i = 0; i < 5; i++)
    ...;
printf("%d", a[i]);    // 你以为打印 a[4]=5，实际访问 a[5] —— 越界！
```

#### 7.5 步进不一定每次加 1

```c
for (i = 2; i <= 50; i += 2)   // 偶数和 = 650
for (i = 1; i <= 50; i += 2)   // 奇数和 = 625
for (i = 10; i >= 1; i -= 2)   // 倒序：10+8+6+4+2 = 30
```

有了第 6 章的复合赋值，`i += 2` 就是 `i = i + 2`，`i -= 3` 就是 `i = i - 3`。

#### 7.6 多变量 for：用逗号放多个

让 `i` 递增、`j` 递减，两头往中间夹：

```c
int i, j;

for (i = 0, j = 9; i < j; i++, j--)    // 初始化两个，步进两个，都用逗号
    printf("i=%d j=%d\n", i, j);
```

输出：

```
i=0 j=9
i=1 j=8
i=2 j=7
i=3 j=6
i=4 j=5
```

分号仍然只有 **2 个**。多打一个（`for (...; ...; ...;)`）会编译报错——编译器以为还有第四段。

#### 7.7 省略大括号的陷阱

**缩排是给「人」看的排版，编译器完全无视它。决定「谁在循环里」的只有 `{ }`。**

```c
sum = 0;
for (i = 1; i <= 3; i++)
    sum += i;
    printf("%d ", sum);      // 缩排骗人：这行其实在循环「外」
printf("\n");
```

`for` 后面没有大括号，循环体就**只有紧跟着的第一句**。上面实际是：

- `sum += i;` 跑 3 遍 → `sum = 1+2+3 = 6`
- `printf` 只跑 1 遍 → 打印 `6`

**输出是 `6`，不是 `1 3 6`。**

实测四种写法（gcc 会给出 `-Wmisleading-indentation` 警告）：

| 写法 | 结果 |
| --- | --- |
| `sum += 10;` 缩排了，看起来像在循环里 | `sum = 16` |
| `sum += 10;` 没缩排，一眼看出在外面 | `sum = 16` |
| 全挤在一行 | `sum = 16` |
| **加大括号**，两句真的都在循环里 | `sum = 36` |

前三行结果一模一样——缩排怎么摆都不影响，只有大括号能改结果。

建议**永远加大括号，哪怕只有一句**。加上之后缩排和真实结构就永远一致，日后往循环里加语句也不会忘补括号。商业代码规范（Google、Linux 内核）都强制要求这么写。

#### 7.8 整数除法与平均值

```c
int sum = 385, n = 10;

printf("%d\n", sum / 10);            // 38    两个 int 相除，小数直接砍掉
printf("%.2f\n", (double)sum / 10);  // 38.50 除之前先转成 double
```

**必须在除之前转类型**：整数除法发生在「除的那一刻」，跟 `printf` 用什么占位符无关。就算写 `printf("%f", sum / 10)`，结果也已经是 38 了——**用 `%f` 也救不回来**。

#### 7.9 当天练习的验证值

```
sum = 5050                  // 1+2+...+100
sum (1..20)  = 210          // for 版
while version = 210         // 改写成 while，输出必须一样
i after loop = 5            // for (i=0; i<5; i++) 结束后 i 的值
sum of even  = 650          // 2+4+...+50
sum of odd   = 625          // 1+3+...+49
5! = 120                    // 1×2×3×4×5
sum of squares = 2870       // 1²+2²+...+20²，写成 i * i
AVG1 = 38                   // 385/10，整数除法（错的示范）
AVG2 = 38.50                // (double)385/10
```

#### 7.10 易错点

- `for` / `if` / `while` 的括号**后面**多写分号 → 循环体变成空语句，白跑一遍。
- `while (i <= 20;)` 括号**里面**多写分号 → 编译报错，`while` 只能放一个条件。
- 循环体里忘了写步进 → 死循环，控制台按 **Ctrl + C** 中断。
- 把 `printf` 写进循环体 → 每轮都打印，要最终结果就放在**循环体外**（右大括号之后）。
- 求积时累加器初值写 0，或从 0 开始乘 → 结果永远是 0。
- 复用累加器做第二个循环时忘了归零 → 得到两个结果之和（如 650+625=1275），**不报错但结果是错的**。
- 照抄上一个程序的范围（题目要 20 却写 100）。

### 第 8 章 break 与 continue

**源文件：`ch_03_break_continue.c`（`ch_03_break_continue`）**

两个都是「满足条件就不按原计划走」，但狠的程度完全不同。我给它们各配了个比方，比定义好记：

| | 比方 | 本轮后面的语句 | `i++` | 后面的轮次 |
| --- | --- | --- | --- | --- |
| **`break`** | **夺门而出** | 不执行 | **不执行** | 一次都不跑 |
| **`continue`** | **安检没过** | 不执行 | **照常执行** | 照常跑 |

`continue` 我早就见过——第 4 章 `compare_two_numbers.c` 里「没找到逗号就重新输入」那句就是它。当时不知道名字，这天正式认领回来。

**两者几乎永远跟 `if` 配对**，因为它们需要一个「什么时候跳」的理由。

#### 8.1 break：满足条件就跑路

```c
sum = 0;
for (i = 1; i <= 10; i++) {
    sum += i;
    if (sum > 15)       // 注意是 > 15，不是 >= 15：sum 刚好等于 15 时不触发
        break;
}
printf("sum = %d, i = %d\n", sum, i);        // 21 6
```

逐轮：

| 轮 | i | `sum += i` 后 | `sum > 15`？ | 有没有 `i++` |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 否 | 有 |
| 2 | 2 | 3 | 否 | 有 |
| 3 | 3 | 6 | 否 | 有 |
| 4 | 4 | 10 | 否 | 有 |
| 5 | 5 | 15 | **否**（15 不大于 15） | 有 |
| 6 | 6 | **21** | 是 → break | **没有** |

#### 8.2 break 时，i 停在哪

**`i` 停在「被跳出去那一轮」的值，因为 `i++` 根本没机会执行。**

这跟昨天学的「正常结束」完全是两条路：

| | 怎么结束的 | `i` 是多少 |
| --- | --- | --- |
| 正常结束 | 条件自己变假，退出 | 第一个不满足条件的（跨过边界一步） |
| **`break`** | 条件还**成立**时被硬跳 | **就是当轮的值**，`i++` 没执行 |

```c
sum = 0;
for (i = 1; i <= 10; i++) {
    if (i == 4)
        break;
    sum += i;
}
printf("sum = %d, i = %d\n", sum, i);        // 6 4
```

`i` 是 **4** 不是 5。如果按昨天那套「终点 +1」算，条件明明是 `i <= 10`，很容易顺手写成 11——错得离谱。

**`i++` 在 `for` 的第三段，只有正常跑完一轮才会执行；`break` 一跳，第三段直接被跳过。**

#### 8.3 break 写前面还是后面，结果不一样

这是这章最实在的一条。两段代码只差一个位置：

```c
/* A：break 在前 */
for (i = 1; i <= 8; i++) {
    if (i == 5) break;      // i=5 这一轮直接走人
    sum += i * 2;
}
// sum = 20, i = 5

/* B：break 在后 */
for (i = 1; i <= 8; i++) {
    sum += i * 2;           // 先加，才判断要不要走
    if (i == 5) break;
}
// sum = 30, i = 5
```

**`sum` 差了 10（就是 `5 * 2`），`i` 却完全一样。**

> **结论：`break` 的位置不影响 `i`，只影响「触发那一轮的语句有没有执行完」。**
> 写在前面 → 那轮的 `i` 不会被加进去；写在后面 → 那轮的 `i` 已经加过了。

#### 8.4 break 没触发时，退化成普通的 for

```c
sum = 0;
for (i = 1; i <= 5; i++) {
    sum += i;
    if (sum > 1000)     // 永远不成立，break 一次都没执行
        break;
}
printf("sum = %d, i = %d\n", sum, i);        // 15 6
```

条件永远不成立时，`break` 形同虚设，这时候**老老实实用昨天那套规则**：`i = 5 + 1 = 6`。

#### 8.5 break 真正用来干什么

前面几段都是「算到某个值就停」，看着像在给自己找麻烦。真正的用途是**找到就停，不用傻跑完**：

```c
int target = 0;
for (i = 1; i <= 100; i++) {
    if (i % 7 == 0) {
        target = i;
        break;          // 找到了就走，后面的不用再试
    }
}
printf("first number divisible by 7: %d, i = %d\n", target, i);   // 7 7
```

**没有 `break` 的话**：循环会一直跑到 `i = 101`，而且 `target` 会被**最后一个**（98）覆盖掉——找「第一个」变成了找「最后一个」。这类 bug 不报错，只是答案不对。

#### 8.6 continue：跳过本轮，下一轮照常来

```c
sum = 0;
for (i = 1; i <= 6; i++) {
    if (i == 3)
        continue;       // i=3 这一轮：后面的 sum += i 不执行
    sum += i;
}
printf("sum = %d, i = %d\n", sum, i);        // 18 7
```

`1+2+4+5+6 = 18`（3 被跳过），**`i` 是 7 不是 3**——`continue` 时 `i++` 照常执行，循环正常跑到结束。

用安检的比方说：`i=3` 被拦下，**但不是重新检查 `i=3`**，而是轮到 `i=4`。要不然就死循环了。

#### 8.7 continue 的位置同样决定执行了多少

```c
sum = 0;
for (i = 1; i <= 6; i++) {
    sum += i;           // 在 continue 前面：每轮都执行
    if (i == 3)
        continue;
    sum += 100;         // 在 continue 后面：i=3 那轮被跳过
}
printf("sum = %d, i = %d\n", sum, i);        // 521 7
```

逐轮：

```
i=1  加i → 1    加100 → 101
i=2  加i → 103  加100 → 203
i=3  加i → 206  continue！跳过 +100   ← 这轮只加了 3，没加 100
i=4  加i → 210  加100 → 310
i=5  加i → 315  加100 → 415
i=6  加i → 421  加100 → 521
```

#### 8.8 continue 放在循环体最后 = 摆设

```c
sum = 0;
for (i = 1; i <= 4; i++) {
    sum += i;
    if (i == 2)
        continue;       // 后面没有任何语句，跳过"空气"
}
printf("sum = %d, i = %d\n", sum, i);        // 10 5
```

**结果跟完全不写 `continue` 一模一样。**

判断方法很简单：**看 `continue` 后面还有没有语句，没有就是摆设。**

#### 8.9 两个并排看，差别最清楚

同一个循环，只换一个关键字：

```c
for (i = 1; i <= 6; i++) {
    if (i == 3) break;      // 夺门而出
    sum += i;
}
// sum = 3,  i = 3     1+2，i 停在 3

for (i = 1; i <= 6; i++) {
    if (i == 3) continue;   // 安检没过
    sum += i;
}
// sum = 18, i = 7     1+2+4+5+6，i 正常跑到 7
```

`sum` 差 15，`i` 差 4——**全在「`i++` 有没有执行」这一条上**。

#### 8.10 一个还没展开的坑

`break` 只跳出**它所在的那一层**。单层循环没歧义；等学到嵌套循环（循环里再放循环），`break` 只跳出最内层，外层照跑。那天就在[第 9 章 9.6](#96-break-只跳出它所在的那一层)，现在先记住「就近」两个字。

#### 8.11 实际输出（13 段全部实测）

```
1) sum = 21, i = 6                      // sum > 15 就停
2) A: sum = 20, i = 5                   // break 在前
3) B: sum = 30, i = 5                   // break 在后
4) sum = 6, i = 4                       // i 停在触发那一轮
5) sum = 15, i = 6                      // break 没触发
6) sum = 80, i = 10                     // 倒序 + i -= 2
7) first number divisible by 7: 7, i = 7
8) break    -> sum = 3,  i = 3
   continue -> sum = 18, i = 7
9) sum = 18, i = 7                      // continue 基本
10) sum = 37, i = 11                    // 跳过所有 3 的倍数
11) sum = 521, i = 7                    // continue 在后
12) sum = 13, i = 0                     // 倒序 + continue
13) sum = 10, i = 5                     // continue 是摆设
```

#### 8.12 易错点

- 把 `break` 之后的 `i` 按「终点 + 1」算 → `break` 时 `i` 停在触发那一轮，`i++` 没执行。
- 以为 `break` 后面那句还会执行 → 触发之后当轮剩下的全部跳过，包括 `i++`。
- 忽略 `break` 的位置 → 写在 `sum += i` 前 / 后，结果差一整轮的增量。
- 把 `continue` 当成 `break` → `continue` 时 `i++` 照常执行，循环能正常结束。
- 以为 `continue` 是「重新检查同一个 `i`」→ 它跳过的是本轮剩余部分，下一轮是**新的 `i`**。
- `continue` 写在循环体最后 → 后面没语句可跳，等于没写。
- `if` 里的条件写错等号 → `sum > 15` 和 `sum >= 15` 差一轮（`sum` 刚好等于 15 时，前者不触发）。

### 第 9 章 if 的三种形态、嵌套循环与跳出多层

**源文件：`if_else_nested.c`（`ch_03_if_else_nested`）**

这天写的第一个程序。`if` 我本来以为自己会了，写的时候才发现真正卡住我的是另外两件事：`else` 到底算谁的，以及循环套上循环之后 `break` 跳到哪儿去。顺带把上一章 8.10 欠着的那个坑（`break` 只跳出一层）补上。

#### 9.1 三种形态

| 形态 | 形状 | 一共执行几条 |
| --- | --- | --- |
| 单 `if` | `if (...) A;` | 0 条或 1 条 |
| `if-else` | `if (...) A; else B;` | **必有且只有**一条 |
| `else-if` 链 | `if ... else if ... else` | 命中第一个就停 |

单 `if` 就是「成立才做，不成立拉倒」。这里有个坑，看这两句：

```c
if (i > 5)
    printf("1) i > 5, printed\n");
printf("   always printed\n");       // 无条件执行
```

第二句跟第一句缩得一样齐，但它**不在 `if` 里**。决定「谁在 `if` 里」的是大括号，不是缩排——第 7 章 `for` 那次已经吃过一次亏了，到这儿又来一遍。

`if-else` 是二选一，A 和 B 必定有一个执行，不可能都跑，也不可能都不跑。

`else-if` 链是从上往下试，**命中第一个就跳出整条链**，后面的条件看都不看。末尾那句 `chain done` 就是证据：跳出来的是 `if` 链，不是整个程序。

#### 9.2 条件得从「严」到「宽」写

`score = 85` 走一遍：

| 顺序 | 条件 | 85 分 | 结果 |
| --- | --- | --- | --- |
| 1 | `>= 90` | 假 | 往下 |
| 2 | `>= 80` | **真** | 打印 B，后面不看了 |
| 3 | `>= 70` | （没轮到） | — |
| `else` | 兜底 | （没轮到） | — |

我一开始觉得顺序无所谓，反正四个条件都写全了。不行：

| 写法 | 85 分被判成 | 90 分被判成 |
| --- | --- | --- |
| `>=90 → >=80 → >=70` | **B**（对） | A（对） |
| `>=60 → >=90 → >=80` | **及格（错）** | 及格（错） |

90 分的人会被第一条 `>=60` 截住，直接判及格。所以**门槛最高的写最前面**，写完之后拿 90、80、70 各试一遍，看它落在哪一档。

#### 9.3 坑一：else 是就近配对的

这两组代码只差 `j` 的正负号：

```c
/* 第一组：i=1, j=1 */
if (i > 0)
    if (j > 0)
        printf("both positive\n");
    else
        printf("???\n");           // 没打印：j>0 成立，走不到这里

/* 第二组：i=1, j=-1 */
if (i > 0)
    if (j > 0)
        printf("inner\n");
    else
        printf("inner else taken (i=%d j=%d)\n", i, j);   // 它打印了！
```

关键在第二组。**外层 `i > 0` 明明是成立的**，要是 `else` 真属于外层，它压根不该执行。我就是看到这行打印出来才反应过来：`else` 跟的是**里面那个 `if (j > 0)`**。

> `else` 永远跟「最近的、还没配对的 `if`」，跟缩排怎么写一毛钱关系没有。

gcc 会给个 `-Wdangling-else` 警告，名字挺形象——悬空 else。

根治办法就是加大括号，加了之后归属写死了：

```c
if (i > 0) {
    if (j > 0) {
        printf("both\n");
    }
}
else {                              /* 现在它真的属于外层了 */
    printf("outer else\n");
}
```

这段只会打印 `braces fix it`。因为 `i > 0` 成立，外层 `else` 本来就不该执行——什么都不打印，恰恰说明归属对了。

#### 9.4 坑二：一个等号

```c
i = 0;
if (i = 5)                          /* 先把 5 装进 i，再判断 i 的真假 */
    printf("5) entered, i becomes %d\n", i);   /* 打印：i becomes 5 */
```

这一个等号干了**两件坏事**，第二件比第一件阴：

1. 条件变成赋值表达式，值是 5，**非零即真** → 永远进得去，`else` 永远走不到。
2. `i` 被悄悄改成 5 了。这个才是真麻烦——后面凡是读到 `i` 的地方全跟着错，而且你压根不会想到是这一行干的。

gcc 警告是 `-Wparentheses`，意思大概是「你是不是想写 `==`」。

后来学到一招：把常量写左边，写成 `if (5 == i)`。这样手抖少写一个等号就成了 `5 = i`，编译器直接报错（不能给常量赋值）；而 `i = 5` 完全合法，编译器只能警告一下，你不看警告就过去了。

#### 9.5 嵌套循环：外层走一步，内层转一圈

```c
for (i = 1; i <= 3; i++) {
    for (j = 1; j <= 2; j++) {      /* 外层每加 1，内层跑完 2 次 */
        printf("   i=%d j=%d\n", i, j);
    }
}
```

口诀：**外层慢、内层快，像时针和分针**。总共 3 × 2 = 6 次。

这个 6 我一开始算成了 5（3+2），看到输出有 6 行才发现——总次数是**乘**不是加。

还有一点我搞错过：以为内层的 `j` 会接着上一轮的 2 往下走。不会，`j = 1` 写在内层 `for` 的第一段，外层每走一步它就重新来一遍，所以永远是 1、2、1、2。

#### 9.6 break 只跳出一层（补 8.10 的坑）

```c
for (i = 1; i <= 3; i++) {
    for (j = 1; j <= 3; j++) {
        if (j == 2)
            break;                  /* 只跳出 for(j) */
        printf("   i=%d j=%d\n", i, j);
    }
    /* 回到这里，外层继续下一轮 i */
}
```

输出：

```
i=1 j=1
i=2 j=1
i=3 j=1
```

内层每次只打印 `j=1`，但**外层 `i` 照样 1、2、3 全跑完**。

`break` 是「就近」的——跳掉自己所在的那一层就完事，外层毫不知情。我把它记成「谁离它近它就跳出谁」。`continue` 也一样，只管自己那一层（见 9.8）。

#### 9.7 想一次跳出多层：举旗

```c
int flag = 0;                   /* 0 = 继续，1 = 停 */
int hit_i = 0, hit_j = 0;

for (i = 1; i <= 5 && !flag; i++) {      /* ★外层条件里加 !flag */
    for (j = 1; j <= 5; j++) {
        if (i * j == 6) {
            flag = 1;           /* 举旗 */
            hit_i = i;
            hit_j = j;
            break;              /* 先跳内层 */
        }
    }
}
```

两步：

1. **内层**命中就 `flag = 1`，然后 `break` 跳出内层。
2. **外层**条件里挂上 `&& !flag`。内层这一轮结束、回到外层判断时，`!flag` 已经是假，外层就退了。

实测 `i*j==6 at i=2 j=3, flag=1`——`i=2 j=3` 命中，外层的 3、4、5 一趟都没跑。

这个套路跟第 4 章 `compare_two_numbers.c` 里的 `ok` 是一模一样的，只是换了个名字叫 `flag`；下一章的 `found` 还是它。都是「举面旗告诉外层：事儿办完了，收工」。

C 里没有「一次跳出好几层」的关键字（`goto` 能干，但没人推荐），举旗是标准写法。

#### 9.8 嵌套里的 continue

```c
sum = 0;
for (i = 1; i <= 3; i++) {
    for (j = 1; j <= 3; j++) {
        if (j == 2)
            continue;           /* 跳过本轮，但 j++ 照常执行 */
        sum += i * j;
    }
}
printf("9) sum=%d i=%d j=%d\n", sum, i, j);   /* 24 4 4 */
```

| `i` | `j = 1` | `j = 2` | `j = 3` | 小计 |
| --- | --- | --- | --- | --- |
| 1 | +1 | 跳过 | +3 | 4 |
| 2 | +2 | 跳过 | +6 | 8 |
| 3 | +3 | 跳过 | +9 | 12 |
| | | | **合计** | **24** |

结束后 `i = 4`、`j = 4`，两层都是**正常结束**的值（终点 + 1）——因为 `continue` 不跳过 `j++`，第 8 章那条规则套在嵌套里照样成立。

#### 9.9 实际输出

```
1) i > 5, printed
   always printed
2) 3 is odd
3) 85 -> B
   chain done
4) both positive
4) inner else taken (i=1 j=-1)
4) braces fix it
5) entered, i becomes 5
5) i == 5 false, i still 0
6) nested:
   i=1 j=1
   i=1 j=2
   i=2 j=1
   i=2 j=2
   i=3 j=1
   i=3 j=2
7) break inner only:
   i=1 j=1
   i=2 j=1
   i=3 j=1
8) i*j==6 at i=2 j=3, flag=1
9) sum=24 i=4 j=4
```

编译时 gcc 会蹦出三条警告：两处 `-Wdangling-else`，一处 `-Wparentheses`。这三个坑是我故意留在代码里的，警告就是编译器在拿手指戳我。

#### 9.10 易错点

- 以为 `else` 跟着缩排走 → 它跟**最近的未配对 `if`**，加大括号才能写死归属。
- 把 `=` 当 `==` → 条件永远为真，还顺手把变量的值改了，这个副作用最难查。
- 以为 `break` 能跳出多层 → 它只跳**自己那一层**，外层照跑（要跳多层就举旗）。
- 嵌套循环的总次数算成加法（3+2）→ 是**乘法**（3×2 = 6）。
- 以为内层 `j` 会接着上一轮 → `j = 1` 在内层第一段，外层每走一步都重新初始化。
- `else-if` 链从宽到严写 → 边界值被前面截胡（90 分被判成及格）。
- 以为命中 `if` 链之后程序就结束了 → 跳出来的只是 `if` 链，后面的语句照常跑。
- 内外层用同一个循环变量（都叫 `i`）→ 内层一动就把外层的计数改了，结果全乱。

### 第 10 章 猜数字游戏：随机数与容错输入

**源文件：`guess_number.c`（`ch_03_guess_number`）**

这天写的第二个程序，也是目前为止最长的一个。前面九章的东西基本全用上了：`while` 循环、`if` 三分支、标记变量、`break`、`continue`，再加上 `scanf` 的返回值。

| 项目 | 规则 |
| --- | --- |
| 范围 | 1 ~ 100（电脑自己想一个数） |
| 机会 | 7 次 |
| 提示 | 太大 / 太小 |
| 输错 | 提示重来，**不扣次数** |

#### 10.1 随机数：srand 播种，rand 取数

```c
#include <stdlib.h>             /* rand / srand */
#include <time.h>               /* time */

srand((unsigned)time(NULL));    /* 播种：整个程序只做一次 */
secret = rand() % 100 + 1;      /* 1~100 */
```

范围是这样推出来的：

| 表达式 | 取值 |
| --- | --- |
| `rand()` | 0 ~ `RAND_MAX` |
| `rand() % 100` | 0 ~ 99 |
| `rand() % 100 + 1` | **1 ~ 100** |

要 `[min, max]` 就写 `rand() % (max - min + 1) + min`。取的是余数，所以有几个值由 `%` 后面那个数说了算。

我第一次只写了 `rand()` 没写 `srand`，结果每次运行出来的都是同一串数，还以为自己哪儿写错了。所以：**`srand` 写一次，写在 `main` 开头。**

写进循环里更糟——同一秒内 `time(NULL)` 是一样的，等于反复播同一个种子，出来的会是同一个数。

> 用到了什么工具就包含什么头文件：`rand` / `srand` 在 `stdlib.h`，`time` 在 `time.h`。

#### 10.2 循环条件挂了两个

```c
while (count < max_try && !found)
```

| 条件 | 管什么 | 变假的时候 |
| --- | --- | --- |
| `count < max_try` | 次数还有没有 | 用完 7 次 → **输了** |
| `!found` | 有没有猜中 | 猜中了 → **赢了** |

`&&` 两边都成立才继续，任意一边变假就退出。退出来之后拿 `if (found)` 分一下是哪种结局：

```c
if (found) printf("You won! ...\n");
else       printf("You lost! ...\n");
```

#### 10.3 scanf 的返回值

```c
ret = scanf("%d", &guess);
```

这个函数我用了三天，才知道它还有返回值。而且**返回的是「读进来了几个」，不是读到的那个数**——数本身在 `guess` 里。

| `ret` | 意思 | 程序怎么处理 |
| --- | --- | --- |
| `1` | 读到一个整数 | 往下走，`count++` |
| `0` | 有输入，但不是整数 | 提示 + 清缓冲区 + `continue` |
| `EOF`（就是 `-1`） | 输入没了（`Ctrl+Z` / 管道到底） | 提示 + `break` |

把它存进 `ret` 是因为下面要判断三次。要是直接写 `if (scanf(...) == 1)` 就只能判一次，而且每多写一个 `scanf` 就真的又去读一次输入，不是「查一下」那么便宜。

#### 10.4 输错不扣次数：看 count++ 放在哪

```c
if (ret != 1) {              /* 读到了但不是整数 */
    printf("  Not a number, try again (this try is FREE)\n");

    while ((ch = getchar()) != '\n' && ch != EOF)
        ;                    /* 空循环体：一直读到行尾，把垃圾清掉 */
    continue;
}

/* 情况三：ret == 1，输入合法，往下走 */
count++;                     /* 走到这儿说明输入合法，次数 +1 */
```

这一小段里塞了三件事：

1. **`continue` 把本轮剩下的全跳过了**——包括下面的 `count++`。所以这一轮不扣次数，下一轮提示符还是 `[1/7]`。
2. **缓冲区必须清**。那个字母不清掉的话，下一轮 `scanf` 又读到它、又判错、又 `continue`……我试过一次，屏幕直接刷疯了。`while ((ch = getchar()) != '\n' && ch != EOF);` 是个空循环体（那个孤零零的分号就是循环体），一路读到换行符为止。
3. **`count++` 放在「确认合法之后」**，这才是「只有有效输入才计数」的真正原因。

顺带说一句，第 8 章讲过「`continue` 后面没语句就是摆设」——这里它后面还跟着 `count++` 和一整个三分支，所以是真在干活。

`ch` 必须是 `int` 不能是 `char`：`getchar` 为了能表示 `EOF`（一般是 `-1`）返回的是 `int`，用 `char` 装有可能永远等不到 `EOF`。

#### 10.5 found 这面旗

```c
else {                     /* 既不小也不大，那就是相等 */
    printf("  *** BINGO! ***\n");
    found = 1;             /* ★举旗 */
    break;
}
```

`found = 1` 和 `break` 两个都写了，各管一摊：

- `break` 当场跳出循环，不用再猜。
- `found = 1` 是给循环**外面**那个 `if` 看的，好让它分清「猜中了」还是「次数用完了」。

我一开始觉得有 `break` 就够了，其实不够——跳是跳出来了，可外面不知道你是怎么出来的，结果赢了也会打印 `You lost!`。

#### 10.6 三分支判断

```c
if (guess < secret)       printf("  Too small!\n");
else if (guess > secret)  printf("  Too big!\n");
else                      printf("  *** BINGO! ***\n");
```

第三个不用写 `else if (guess == secret)`——既不小也不大，那就是相等。这么写还有个好处：三个分支必有且只有一个执行，不会漏情况。

#### 10.7 7 次够不够

每次猜当前范围的正中间，范围就对半砍：

| 第几次 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 还剩几个可能 | 50 | 25 | 12 | 6 | 3 | 1 | 0 |

`log₂100 ≈ 6.64`，而 `2⁷ = 128 > 100`，所以 **7 次是够的**——这游戏不靠运气，靠的是每次砍一半。

#### 10.8 实际输出

> `secret` 每次运行都不一样，下面四段是同一局（答案为 90）的实录。

**① 猜中了（用了 6 次）**

```
=== Guess the number (1-100), 7 tries ===
[1/7] Your guess:   Too small!
[2/7] Your guess:   Too small!
[3/7] Your guess:   Too small!
[4/7] Your guess:   Too big!
[5/7] Your guess:   Too big!
[6/7] Your guess:   *** BINGO! ***
You won! Answer = 90, used 6 tries.
```

**② 输错不扣次数（`abc` 那轮是免费的）**

```
[1/7] Your guess:   Too small!
[2/7] Your guess:   Not a number, try again (this try is FREE)
[2/7] Your guess:   Too small!
```

**③ 数字后面粘了字母（`50abc`）**

```
[1/7] Your guess:   Too small!                                  <- scanf 读走 50，返回 1
[2/7] Your guess:   Not a number, try again (this try is FREE)  <- 剩下的 abc 被下一轮读到
[2/7] Your guess:   *** BINGO! ***
You won! Answer = 90, used 2 tries.
```

`scanf("%d")` 碰到 `50abc` 会读走 `50` 就停，`abc` 留在缓冲区里，下一轮才被判成非法输入——所以它会「慢一拍」才报错。这个是试出来的，我盯着 `[2/7]` 出现两次才想明白。

**④ 输入结束 / 次数用完**

```
[1/7] Your guess:   Too small!
[2/7] Your guess:   Input closed. Game over.
You lost! Answer was 90. (used 1 tries)
```

```
[7/7] Your guess:   Too small!
You lost! Answer was 90. (used 7 tries)
```

#### 10.9 易错点

- `scanf` 后面漏 `&` → `scanf("%d", guess)` 是错的。
- 把返回值当读到的数：`guess = scanf("%d", &guess)` → `guess` 里装的是 1 或 0。
- 忘了 `srand` → 每次运行都是同一串数，游戏不随机。
- 把 `srand` 写进循环 → 反复播同一个种子，出的数不变。
- 输错不清缓冲区 → 同一个字母被反复读到，死循环刷屏。
- 清缓冲区的 `ch` 声明成 `char` → 可能永远等不到 `EOF`。
- `count++` 写在 `continue` **前面** → 输错也扣次数，跟「this try is FREE」对不上。
- 猜中时只写 `break` 忘了 `found = 1` → 赢了却打印 `You lost!`。
- `rand() % 100` 是 0~99，漏掉 `+1` → 范围变成 0~99，`secret` 可能是 0。
- 三分支写成两个独立的 `if` → 每次都判断两遍；用 `else-if` 链命中就停。
